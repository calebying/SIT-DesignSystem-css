# SIT Canvas — Design Token Reference

This is a reference for every design token this framework ships, generated by reading the actual
source (`sass/_root.scss`, `sass/_variables.scss`) and the compiled output (`css/sit-canvas.css`) —
not hand-guessed. It reflects the framework as of this document's commit; regenerate the tables
below after any token change (see [Regenerating this doc](#regenerating-this-doc)).

## Two kinds of token in this framework

SIT Canvas ships two genuinely different kinds of "token", and it matters which one you're using:

1. **CSS custom properties** (`--sit-canvas-*`) — real runtime `var(...)` values, set on `:root`
   or on a component's own base selector (e.g. `.btn`, `.alert`). You can override these in the
   browser, in devtools, or in your own stylesheet, with no rebuild — e.g.
   `.my-widget { --sit-canvas-btn-border-radius: 0; }`.
2. **SCSS `!default` variables** (`$font-size-base`, `$box-shadow`, `$spacers`, …) — compile-time
   only. Bootstrap 5.2's utility classes (spacing, elevation, z-index) and typography scale are
   *not* re-exposed as CSS custom properties in this version — changing them means overriding the
   Sass variable and rebuilding, not setting a CSS variable at runtime.

Every custom property in this codebase is emitted through Sass's `$variable-prefix` (set to
`sit-canvas-` in `sass/_variables.scss:425`) via `--#{$variable-prefix}token-name` — that's what
makes every one of them come out as `--sit-canvas-token-name` in the compiled CSS. See
`sass/_functions.scss`/`sass/_badge.scss` for the pattern in use.

> **Known naming gap (P0-01 / P4-04):** at the time of writing, `--section-padding`,
> `-xs`, `-sm`, `-lg`, `-xl` (consumed by `sass/_section.scss`) are the **only** custom properties
> in this codebase that don't follow the `--sit-canvas-*` prefix convention, and they're only
> defined inside the `lg` breakpoint (a separate, real bug — section padding is `0` below 992px).
> Both are being fixed in a separate PR (`fix/section-padding-breakpoint`); once merged, these
> become `--sit-canvas-section-padding` / `-xs` / `-sm` / `-lg` / `-xl`, defined at both a
> mobile-first base and the `lg` breakpoint. This table will need a small update after that PR
> lands — see the regeneration note at the bottom.

These live in `sass/_root.scss`'s `:root { … }` block and apply framework-wide. Source: the first
`:root { … }` in the compiled `css/sit-canvas.css`.

> **Known gap (P4-05, not fixed here — palette decision, not a mechanical fix):**
> `--sit-canvas-dark` (`#000`), `sass/_variables.scss`'s `$gray-800`, and `$gray-900` are all
> literally `#000` — three redundant "pure black" tokens with no distinct dark-mode-ready ramp.

## Foundation tokens (SCSS-only — not CSS custom properties)

These control compile-time output only; there's no `var(--sit-canvas-*)` to override them at
runtime in this version. All from `sass/_variables.scss`.

## Regenerating this doc

This was generated by:

1. `npm run build` (produces a fresh `css/sit-canvas.css`).
2. `grep -o -- '--sit-canvas-[a-zA-Z0-9-]*:[^;]*;' css/sit-canvas.css` to enumerate raw tokens and
   spot-check values, and targeted lookups of each component's base selector (e.g. `.btn{…}`,
   `.alert{…}`) in the compiled output for the "base defaults" column above.
3. Reading `sass/_root.scss` for what's global, and `sass/_variables.scss` for the SCSS-only
   foundation scales (spacing, typography, elevation, z-index) that never became CSS custom
   properties in this version.

Re-run the same process after any token addition/rename/removal — especially after
`fix/section-padding-breakpoint` (P0-01/P4-04) merges, which renames the 5 `--section-padding*`
tokens documented above under their own heading.
